你提到的：

- U2I 双塔召回

- 向量 I2I

都非常符合短视频推荐的常见技术主线。短视频推荐和电商推荐、广告推荐最大的区别在于：**它更依赖隐式反馈、更重视连续消费、更受视频时长和内容新鲜度影响，也更强调用户即时兴趣和沉浸体验。**

# 一、短视频推荐业务的核心特点

## 1. 用户反馈以隐式行为为主

短视频场景里，用户不一定会点赞、评论、关注，但会通过行为表达兴趣：

```text
是否点击/播放
观看时长
播放完成率
是否快速划走
是否复播
是否点赞
是否评论
是否分享
是否关注作者
是否点不感兴趣
是否进入主页
是否连续观看同类视频
```

其中最核心的是：

```text
播放时长 / 完播率 / 有效播放 / 快划
```

这和电商推荐不同。电商有点击、加购、下单等强转化信号；短视频很多时候没有明确转化，用户“看得久”本身就是目标。

---

## 2. 视频时长对目标有强干扰

短视频推荐里一个非常经典的问题是：

> 视频越长，天然获得更长播放时长的机会越大；视频越短，天然更容易完播。

所以直接优化播放时长，会偏向长视频；直接优化完播率，会偏向短视频。

例如：

| 视频 | 时长 | 用户观看 | 播放时长 | 完播率 |
|---|---:|---:|---:|---:|
| A | 10 秒 | 9 秒 | 9 秒 | 90% |
| B | 120 秒 | 40 秒 | 40 秒 | 33% |

如果只看播放时长，B 更好；如果只看完播率，A 更好。  
但真实用户满意度不一定这么简单。

所以短视频精排里经常做：

```text
播放时长目标消偏
完播率目标消偏
分位数目标
时长归一化
duration-aware calibration
```

你提到的“分位数目标消偏”就是非常典型的视频推荐技术点。

---

## 3. 用户兴趣强烈短期化、session 化

短视频信息流是连续消费场景，用户兴趣变化很快。

用户可能上午刷：

```text
财经、AI、汽车
```

中午刷：

```text
美食、搞笑、健身
```

晚上刷：

```text
电影解说、游戏、情感
```

所以短视频推荐非常依赖：

```text
实时行为
短期序列
session 兴趣
当前上下文
最近几刷反馈
```

相比电商，短视频推荐中“最近 5 次、10 次、30 次行为”的价值更高。

---

## 4. 内容供给变化快，新内容冷启动重要

短视频内容生命周期很短：

```text
新视频大量产生
热点快速变化
爆款生命周期短
老视频容易衰退
```

因此召回和排序都要考虑：

```text
新视频探索
作者冷启动
热点内容注入
时效性
内容生命周期建模
```

否则系统会过度推荐历史高热内容，导致新内容起不来。

---

## 5. 负反馈非常重要

短视频里“划走”是非常强的负反馈。

常见负反馈包括：

```text
曝光后极短观看
秒划
不感兴趣
拉黑作者
举报
连续多次跳过同类内容
播放但很快退出
```

这些信号对召回和精排都很关键。

---

## 6. 推荐结果需要多样性和节奏感

短视频是沉浸式 feed，如果连续刷到相似内容，用户容易疲劳。

所以需要控制：

```text
类目多样性
作者多样性
视频类型多样性
时长多样性
新老内容混排
探索/利用平衡
重复内容打压
```

这不仅是重排问题，召回和精排也要参与。

---

# 二、短视频召回算法常见迭代方向

你提到的召回分支包括：

```text
U2I 双塔
KV 分支
ItemCF
向量 I2I
```

我分别展开。

---

# 1. U2I 双塔召回迭代方向

U2I 双塔是短视频推荐最常见的主召回之一：

```text
User Tower → user embedding
Item Tower → video embedding
ANN 检索 topK 视频
```

## 1.1 基础双塔方案

### 输入

User Tower：

```text
用户画像
历史观看视频序列
历史点赞/关注/分享行为
负反馈行为
实时 session 行为
设备、地域、时间、网络环境
```

Item Tower：

```text
视频 ID
作者 ID
类目/标签
标题文本
封面图
音频/视觉 embedding
发布时间
视频时长
热视频统计特征
```

### 训练目标

常见目标：

```text
点击/播放
有效播放
长播
完播
点赞
关注
分享
复播
```

短视频召回更常用：

```text
有效播放 / 长播 / 完播消偏目标
```

而不是单纯点击。

---

## 1.2 迭代方向一：从单兴趣向多兴趣召回升级

短视频用户兴趣天然多样，一个 user embedding 往往不够。

例如一个用户同时喜欢：

```text
AI 技术
汽车测评
搞笑段子
健身
美食
```

如果只用一个向量，会把多种兴趣平均掉。

### 方案

将 User Tower 改成多兴趣结构：

```text
用户行为序列
→ Capsule / MIND / ComiRec / Transformer
→ 输出多个 user interest embedding
→ 每个 embedding 分别 ANN 召回
```

### 应用到召回

```text
interest_1 → 召回 AI 视频
interest_2 → 召回 汽车视频
interest_3 → 召回 搞笑视频
```

最后多路去重融合。

### 项目亮点

可以说：

> 针对短视频用户兴趣多峰、单向量表达不足的问题，将 U2I 双塔从单 user embedding 升级为多兴趣召回，提升召回覆盖和类目多样性，尤其改善长尾兴趣召回。

---

## 1.3 迭代方向二：引入短期 session 兴趣

短视频实时兴趣很强，长期画像不一定代表当前兴趣。

### 方案

User Tower 拆成：

```text
长期兴趣塔：历史 30 天/90 天行为
短期兴趣塔：最近 N 次播放、点赞、完播、快划
实时 session 塔：当前会话内最近行为
```

融合方式：

```text
user_emb = gate(long_emb, short_emb, session_emb)
```

或者输出多向量：

```text
long_interest_emb
short_interest_emb
session_interest_emb
```

### 应用到召回

```text
长期兴趣召回：保证稳定偏好
短期兴趣召回：追随最近兴趣
session 召回：承接连续消费
```

### 面试表达

> 短视频用户兴趣随 session 快速变化，因此我们在 U2I 召回中增加短期行为建模分支，将最近观看、完播、点赞和秒划行为编码为 session embedding，并通过 gating 与长期兴趣融合，提升连续刷视频场景下的兴趣承接能力。

---

## 1.4 迭代方向三：行为加权和负反馈建模

短视频行为不是简单正负样本。

观看 1 秒划走和完整看完是完全不同的反馈。

### 行为权重设计

可以给不同反馈不同权重：

```text
完播 > 长播 > 点赞 > 评论 > 分享 > 关注
快划 / 不感兴趣 / 举报 为负反馈
```

例如训练样本权重：

```text
watch_time_weight
completion_weight
like_weight
share_weight
negative_feedback_weight
```

### 召回训练目标

可以做加权 contrastive learning：

```text
正样本：长播、完播、点赞、分享、关注
弱正样本：普通播放
负样本：曝光未播、秒划、不感兴趣
hard negative：同类目但秒划的视频
```

### 应用价值

提升召回候选质量，减少“看起来相关但用户不喜欢”的视频。

---

## 1.5 迭代方向四：时长消偏目标用于召回训练

视频时长会影响召回模型学习。

如果直接用 watch time 做标签，模型容易偏向长视频；  
如果直接用 completion rate，模型容易偏向短视频。

### 方案一：分位数目标

对每个视频时长桶计算观看表现分位数。

例如：

```text
duration_bucket = [0-10s, 10-30s, 30-60s, 60-180s]
label = percentile(watch_time | duration_bucket)
```

一个 15 秒视频看 12 秒，可能在同长度视频中是 80 分位；  
一个 120 秒视频看 40 秒，可能在同长度视频中也是 80 分位。

这样二者可以公平比较。

### 方案二：normalized watch time

```text
normalized_watch_time = watch_time / expected_watch_time(duration)
```

其中 expected_watch_time 可以由时长桶统计得到。

### 应用到 U2I 召回

把原来的二分类标签：

```text
是否播放 / 是否长播
```

改成：

```text
分位数长播目标
时长消偏有效播放目标
```

或多任务：

```text
play
long_view_quantile
completion_quantile
like
follow
```

### 项目亮点

> 在 U2I 召回训练中引入 duration-aware 分位数目标，缓解播放时长对长视频的天然偏置，以及完播率对短视频的天然偏置，使召回模型更准确学习用户真实满意度。

---

## 1.6 迭代方向五：hard negative mining

短视频召回非常需要 hard negative。

随机负样本太容易，模型学不到边界。

### 常见 hard negative

```text
曝光但秒划的视频
同类目但低观看的视频
同作者但用户不感兴趣的视频
召回命中但精排低分的视频
ANN 近邻但用户未点击/快划的视频
热门但用户跳过的视频
```

### 应用到双塔

训练时构造：

```text
in-batch negative
random negative
popularity negative
same-category hard negative
exposed-skip hard negative
ANN hard negative
```

### 效果

提升 embedding 空间区分能力，减少泛化过度。

---

## 1.7 迭代方向六：内容多模态 embedding 增强

短视频 item 侧非常依赖内容理解。

Item Tower 可以加入：

```text
标题文本 embedding
ASR 文本 embedding
OCR 文本 embedding
封面图 embedding
视频帧视觉 embedding
音频 embedding
作者 embedding
标签 embedding
```

### 应用方式

```text
item_emb = fusion(id_emb, text_emb, vision_emb, audio_emb, author_emb, tag_emb)
```

新视频没有充分行为时，内容 embedding 尤其重要。

### 项目价值

改善：

```text
新视频冷启动
低互动视频召回
内容语义召回
长尾视频召回
```

---

# 2. KV 召回 / KV 分支迭代方向

你说的 KV 分支在不同团队里可能含义不同。常见有两类：

## 类型 A：召回侧的 Key-Value 倒排召回

也就是：

```text
Key = 用户兴趣 key
Value = 视频候选集合
```

Key 可以是：

```text
类目
标签
作者
话题
音乐
视频聚类簇
embedding cluster
关键词
兴趣实体
```

用户画像中有多个 key，根据 key 查 value list 召回视频。

---

## 2.1 KV 召回的价值

KV 召回优点：

```text
速度快
可解释
覆盖稳定
适合热点、新视频、运营策略
容易做冷启动
```

双塔召回偏语义泛化，KV 召回偏明确兴趣匹配。

---

## 2.2 KV 召回迭代方向一：兴趣 key 质量升级

原始 key 可能来自：

```text
用户观看类目
点赞标签
关注作者
搜索词
视频主题
```

可以升级为：

```text
多模态内容标签
LLM 生成主题标签
视频聚类簇 ID
用户短期 session key
负反馈过滤 key
```

### 应用

用户最近连续完播“露营装备”视频：

```text
key: 露营
key: 户外装备
key: 自驾游
key: 帐篷测评
```

查对应倒排表召回新视频。

---

## 2.3 KV 召回迭代方向二：value list 排序优化

一个 key 下可能有大量视频，不能简单按热度排序。

可以按：

```text
视频质量分
新鲜度
同 key 内个性化分
作者质量
用户历史反馈
内容多样性
负反馈率
```

构造 value list。

例如：

```text
score = quality_score × freshness_decay × personalized_match × diversity_factor
```

### 项目亮点

> 对 KV 召回分支，从简单 key-hit 升级为 key 下个性化排序，综合视频质量、时效性和用户短期兴趣，提升 KV 分支召回候选质量。

---

## 2.4 KV 召回迭代方向三：短期 key 和长期 key 分离

长期 key：

```text
健身
汽车
数码
财经
```

短期 key：

```text
高考志愿
世界杯
某个热点事件
某个电视剧
```

短视频场景强烈需要短期 key。

### 方案

```text
长期 key 召回：稳定兴趣
短期 key 召回：最近 session 兴趣
热点 key 召回：趋势内容
```

在融合时给不同配额：

```text
long_kv_quota
short_kv_quota
hot_kv_quota
```

---

## 类型 B：精排/粗排模型里的 Key-Value 行为序列分支

另一类 KV 分支是：

```text
K = 用户历史行为 item/内容特征
V = 用户对这些内容的反馈强度
```

当前候选 item 作为 query，与历史 K 做 attention，聚合 V。

这类似 DIN / target attention：

```text
candidate item embedding as Query
history item embeddings as Key
history feedback embeddings as Value
```

### 应用到精排

对每个候选视频，根据它和用户历史行为的相关性，动态抽取用户兴趣。

```text
attention(candidate, user_history)
→ behavior_interest_emb
→ ranking model
```

### 适合短视频的改造

Value 中加入：

```text
观看时长
完播率
点赞
评论
分享
快划
不感兴趣
行为时间间隔
视频时长
```

这样模型知道用户对历史视频到底是喜欢还是讨厌。

---

# 3. ItemCF 召回迭代方向

ItemCF 在短视频里非常常用，尤其适合：

```text
看了 A，又看 B
完播 A，又完播 B
点赞 A，又关注 B 作者
```

## 3.1 基础 ItemCF

根据用户共现行为构建 item-item 相似度：

```text
sim(i, j) = cooccur(i, j) / sqrt(pop(i) * pop(j))
```

用户最近看过视频 i，则召回相似视频 j。

---

## 3.2 短视频 ItemCF 的业务改造

短视频不能简单用“播放共现”。

需要行为加权：

```text
完播共现权重大
长播共现权重大
点赞/分享/关注权重大
秒划共现权重低或负
```

例如：

```text
weight(action) =
  完播: 3.0
  长播: 2.0
  点赞: 4.0
  分享: 5.0
  快划: -1.0
```

共现窗口也要考虑顺序：

```text
同 session 内共现 > 跨天共现
短时间间隔共现 > 长时间间隔共现
```

---

## 3.3 迭代方向一：时间衰减 ItemCF

用户最近行为更重要：

```text
weight = exp(-delta_time / tau)
```

应用：

```text
最近 10 分钟完播的视频触发 I2I 权重更高
```

适合承接 session 兴趣。

---

## 3.4 迭代方向二：快划负反馈 ItemCF

如果用户看了 A 之后，对 B 秒划，说明 A 和 B 虽然相似，但 B 不适合该用户。

可以在用户侧过滤：

```text
若用户对某类视频频繁秒划，则降低该类 ItemCF 召回权重
```

或者构造负共现：

```text
positive co-watch
negative co-skip
```

---

## 3.5 迭代方向三：Swing / Graph-based CF

普通 ItemCF 容易受热门视频影响。

Swing 思路是降低重度用户、热门 item 的过度贡献。

适合短视频，因为短视频用户行为量大，热门视频容易污染共现关系。

### 应用

构造用户-视频二部图：

```text
user - item
```

根据共同用户计算 item 相似度，但对高活跃用户和热门 item 降权。

可以改善：

```text
热门视频泛滥
item 相似度不精准
长尾视频召回不足
```

---

## 3.6 迭代方向四：多行为 ItemCF

分别构建多张图：

```text
播放图
长播图
完播图
点赞图
分享图
关注图
负反馈图
```

每张图产生一个 ItemCF 召回分支。

融合时根据用户偏好和场景配额：

```text
完播 ItemCF
点赞 ItemCF
关注作者 ItemCF
复播 ItemCF
```

这样比单一播放共现更细。

---

# 4. 向量 I2I 召回迭代方向

向量 I2I 和 ItemCF 类似，都是从 trigger item 召回相似 item，但区别是：

```text
ItemCF：基于行为共现
向量 I2I：基于 item embedding 近邻
```

Embedding 可以来自：

```text
双塔 item tower
内容多模态模型
图模型
自监督模型
精排中间层
```

---

## 4.1 向量 I2I 基础方案

用户最近行为作为 trigger：

```text
最近完播视频
最近点赞视频
最近关注作者视频
```

对每个 trigger item 查 ANN：

```text
item_emb(trigger) → topK similar videos
```

---

## 4.2 迭代方向一：trigger 行为选择优化

不是所有历史行为都适合作为 trigger。

优先选择：

```text
完播
长播
点赞
分享
关注
复播
最近行为
```

降低或过滤：

```text
秒划
低观看
负反馈
过老行为
```

可以根据行为权重采样 trigger。

---

## 4.3 迭代方向二：多 embedding 空间 I2I

短视频相似性有多种：

```text
内容相似
作者相似
主题相似
视觉相似
音乐相似
用户行为相似
消费意图相似
```

可以构建多套 embedding：

```text
content_i2i
behavior_i2i
author_i2i
topic_i2i
multimodal_i2i
```

每套 embedding 对应不同召回分支。

### 例子

用户完播一个“汽车测评”视频：

```text
behavior_i2i → 召回用户也常看的车评视频
content_i2i → 召回语义相似车评视频
author_i2i → 召回同作者/相似作者视频
topic_i2i → 召回新能源、油耗、试驾相关视频
```

---

## 4.4 迭代方向三：新视频冷启动 I2I

新视频没有行为共现，ItemCF 召不出来。

向量 I2I 可以使用内容 embedding：

```text
标题 + ASR + OCR + 视频帧 + 标签
→ content embedding
→ ANN 检索相似热视频/用户兴趣
```

新视频可以挂到相似热视频下面，通过 I2I 被召回。

---

## 4.5 迭代方向四：I2I 召回结果去重和多样性

I2I 很容易召回一堆高度相似视频，导致 feed 重复。

需要控制：

```text
同作者数量
同主题数量
同音频模板数量
同视频模版数量
近重复内容
```

可以在召回后做：

```text
near-duplicate filter
author cap
topic cap
embedding cluster diversity
```

---

# 三、短视频精排模型常见迭代方向

精排是短视频推荐的核心，目标通常是多目标融合。

---

# 1. 多目标建模

短视频精排不是简单预测 CTR，而是预测多个目标：

```text
play
watch_time
effective_view
long_view
completion
like
comment
share
follow
profile_click
dislike
skip
report
retention
```

## 1.1 常见模型结构

```text
Shared Bottom + 多 task head
MMoE
PLE
ESMM
AITM
DSSM + DeepFM
DIN/DIEN/Transformer 序列模型
```

### 推荐结构

短视频常用：

```text
底层共享 embedding
+ 序列兴趣模块
+ MMoE/PLE 多任务
+ 多个目标 head
```

---

## 1.2 多目标融合

最终排序分可能是：

```text
score =
  w1 * p_effective_view
+ w2 * E[watch_time]
+ w3 * p_like
+ w4 * p_follow
+ w5 * p_share
- w6 * p_skip
- w7 * p_dislike
```

也可以做非线性融合：

```text
score = rank_model_output calibrated by business weights
```

### 业务特点

不同阶段权重不同：

```text
新用户：完播/停留更重要
老用户：长期留存更重要
内容生态：作者公平和多样性也重要
商业化场景：转化或广告收益重要
```

---

# 2. 分位数目标消偏

这是你提到的重点，也是短视频精排非常典型的迭代。

## 2.1 为什么需要分位数目标？

播放时长强依赖视频长度。

如果直接预测 watch_time：

```text
长视频天然占优
```

如果直接预测 completion rate：

```text
短视频天然占优
```

分位数目标可以让不同长度视频在同一相对标准下比较。

---

## 2.2 具体做法

按视频时长分桶：

```text
0-5s
5-10s
10-30s
30-60s
60-180s
180s+
```

在每个桶内统计用户观看时长分布。

对样本计算：

```text
quantile_label = percentile(watch_time | duration_bucket)
```

或者：

```text
quantile_label = percentile(play_ratio | duration_bucket)
```

例如：

```text
15 秒视频看 12 秒，在 10-30s 桶内排 85 分位
120 秒视频看 40 秒，在 60-180s 桶内排 80 分位
```

它们都代表“相对于同长度视频表现较好”。

---

## 2.3 应用到精排

增加一个任务 head：

```text
p_watch_quantile
```

或者直接回归：

```text
watch_quantile_score
```

最终排序融合：

```text
score =
  a * p_long_view
+ b * watch_quantile_score
+ c * p_like
+ d * p_follow
- e * p_skip
```

也可以替代原 watch_time 目标：

```text
raw_watch_time → quantile_watch_time
```

---

## 2.4 应用到召回

U2I 双塔训练时，正样本不再只看：

```text
watch_time > threshold
```

而是：

```text
quantile_label > 0.7
```

或者用 quantile label 作为样本权重。

例如：

```text
sample_weight = 1 + alpha * quantile_label
```

这样召回不会过度偏长视频或短视频。

---

# 3. 快划 / 负反馈建模

短视频精排里，快划是非常强的负反馈。

## 3.1 目标定义

```text
skip = watch_time < 2s
quick_skip = watch_time < min(2s, 0.1 * duration)
dislike = 不感兴趣/拉黑/举报
```

## 3.2 模型应用

增加负反馈 head：

```text
p_skip
p_dislike
p_report
```

排序分扣分：

```text
score = positive_score - λ1 * p_skip - λ2 * p_dislike
```

## 3.3 业务价值

减少用户一刷即走的视频，提升 feed 连续消费体验。

---

# 4. 序列兴趣建模

短视频精排非常依赖用户行为序列。

## 4.1 DIN / Target Attention

对候选视频和用户历史视频做 attention：

```text
attention(candidate_item, user_history)
```

让模型动态找到与候选相关的历史兴趣。

### 应用

候选是“汽车测评”视频，模型会重点关注用户历史中的：

```text
汽车
新能源
试驾
油耗
```

而不是关注用户其他无关行为。

---

## 4.2 Transformer 序列建模

用 Transformer 编码用户最近 N 个行为：

```text
video_id
author_id
category
watch_time
completion
like
skip
time_gap
duration
```

输出 session embedding 或 sequence embedding。

### 短视频特化

行为 token 不只是 item id，还要包含反馈：

```text
item_id + action_type + watch_level + time_gap
```

例如：

```text
完播汽车视频
秒划美妆视频
点赞健身视频
```

这比只记录 item id 更符合短视频反馈特点。

---

## 4.3 长短期兴趣分离

模型中显式分离：

```text
长期兴趣：历史稳定偏好
短期兴趣：最近 session 兴趣
即时反馈：最近几刷行为
```

融合方式：

```text
gate = f(context, user_state)
final_interest = gate * short_interest + (1-gate) * long_interest
```

---

# 5. 新鲜度和生命周期建模

短视频内容生命周期短。

## 5.1 特征

```text
发布时间
内容年龄
曝光增长速度
点击增长速度
完播增长速度
互动增长速度
作者历史质量
热点趋势分
```

## 5.2 模型做法

增加 freshness 特征，或单独 head：

```text
p_future_hot
p_decay
```

也可以在排序分中加入：

```text
freshness_boost
```

但要防止低质新视频过度曝光。

---

# 6. 作者生态建模

短视频不只是推荐视频，也是在分发作者内容。

需要考虑：

```text
作者质量
作者垂类
作者粉丝关系
用户是否关注作者
用户是否看过该作者
作者内容稳定性
作者负反馈率
作者新内容探索
```

## 应用到精排

增加作者侧特征：

```text
author_id embedding
author_category
author_quality_score
author_follow_relation
author_recent_perf
```

排序后还要做：

```text
同作者频控
作者多样性
新作者探索
```

---

# 7. 内容质量建模

短视频有大量低质、搬运、标题党、重复内容。

精排需要加入内容质量分：

```text
清晰度
原创度
低质概率
重复概率
封面质量
标题党概率
违规风险
用户投诉率
负反馈率
```

排序时：

```text
score = engagement_score + quality_score - risk_score
```

---

# 8. 多样性和疲劳控制

短视频如果连续推荐同类内容，用户容易疲劳。

## 8.1 精排模型内建模

加入特征：

```text
用户最近已曝光类目
同类目连续次数
同作者连续次数
相似视频连续次数
```

模型学习疲劳效应。

## 8.2 重排阶段控制

```text
author cap
category cap
topic diversity
embedding MMR
near-duplicate filter
duration mix
freshness mix
```

但这不只是重排，精排分也可以加入 fatigue penalty。

---

# 9. 长期价值建模

短视频如果只优化短期 watch time，可能导致：

```text
沉迷但低满意
标题党
低质刺激内容
用户长期流失
```

所以需要长期目标：

```text
次日留存
7 日留存
长期活跃
用户满意度
负反馈减少
内容生态健康
```

## 应用

训练长期价值模型：

```text
p_retention
p_return
long_term_value
```

最终排序融合：

```text
score = short_term_engagement + λ * long_term_value
```

或者做 delayed feedback 建模。

---

# 10. 校准和分桶建模

短视频不同人群、类目、时长分布差异很大。

需要做 calibration：

```text
按时长桶校准
按类目校准
按用户活跃度校准
按新老用户校准
按新老视频校准
```

例如模型预测完播率在长视频上系统性偏低，就需要分桶校准。

---

# 四、召回和精排都常用的短视频特化技术点

下面整理成一个表，方便你准备项目和面试。

| 技术点 | 业务问题 | 应用到召回 | 应用到精排 |
|---|---|---|---|
| 分位数目标消偏 | 视频时长偏置 | 用分位数长播作为正样本/权重 | 增加 quantile watch head |
| 多兴趣建模 | 用户兴趣多峰 | 多向量 U2I 召回 | 多兴趣序列 attention |
| session 兴趣 | 兴趣变化快 | 短期 U2I/KV/I2I 召回 | 实时序列特征、短期兴趣塔 |
| 快划负反馈 | 隐式负反馈强 | 负样本、hard negative | p_skip head 扣分 |
| 多模态内容理解 | 新视频冷启动 | 内容向量召回、I2I | item 特征增强 |
| hard negative | 召回候选噪声 | 双塔对比学习 | 排序训练困难样本 |
| 作者建模 | 作者生态重要 | 作者召回、相似作者召回 | author embedding、频控 |
| 新鲜度建模 | 内容生命周期短 | 新视频召回、热度召回 | freshness boost/decay |
| 多行为建模 | 行为价值不同 | 多行为 ItemCF/U2I | 多任务模型 |
| 多样性控制 | 用户容易疲劳 | 召回配额、多路召回 | 重排/MMR/fatigue 特征 |
| 长期价值 | 防止短期刺激 | 高质量召回源加权 | retention/LTV head |
| 校准 | 不同桶分布差异 | 召回源分桶阈值 | 分桶校准、score calibration |

# 五、如果包装成“短视频推荐算法迭代项目”，可以这样设计

## 项目一：U2I 召回升级

### 背景

原 U2I 双塔主要基于点击/播放训练，存在：

```text
短视频时长偏置
单兴趣表达不足
短期兴趣承接弱
负反馈利用不足
```

### 方案

```text
1. 引入多兴趣 user tower
2. 增加 session 行为分支
3. 训练目标从播放升级为分位数长播/有效播放
4. 引入快划 hard negative
5. item tower 加入多模态内容 embedding
```

### 指标

```text
召回 HitRate@K
长播 Recall@K
完播 Recall@K
召回多样性
新视频覆盖率
线上人均播放时长
有效播放率
快划率下降
```

---

## 项目二：ItemCF / I2I 召回优化

### 背景

原 ItemCF 主要按播放共现，容易热门偏置、相似度粗糙、短期兴趣响应不足。

### 方案

```text
1. 行为加权共现：完播/点赞/分享高权重，快划负权重
2. 时间衰减：强化 session 内共现
3. Swing 降低热门视频和高活跃用户干扰
4. 多图 ItemCF：完播图、点赞图、关注图、负反馈图
5. 向量 I2I 引入多模态 embedding，解决新视频冷启动
```

### 指标

```text
I2I 点击率
长播率
完播率
新视频召回占比
重复曝光率下降
同质化下降
```

---

## 项目三：精排多目标和时长消偏

### 背景

原精排主要优化播放时长，导致长视频偏置；优化完播率又偏短视频，排序目标和用户满意度不完全一致。

### 方案

```text
1. 构建多任务模型：播放、长播、完播、点赞、关注、分享、快划
2. 引入 duration bucket 分位数观看目标
3. 增加 p_skip/p_dislike 负反馈 head
4. 使用 DIN/Transformer 建模短期 session 兴趣
5. 分桶 calibration 校准不同视频时长/类目上的预测偏差
```

### 指标

```text
人均观看时长
有效播放率
长播率
完播率
快划率下降
点赞/关注/分享提升
次日留存
不同视频时长桶分布更均衡
```

# 六、重点技术点展开：分位数目标消偏

你可以在面试中重点讲这个，因为它很体现短视频业务理解。

## 1. 问题

短视频排序中，直接优化播放时长会偏向长视频；直接优化完播率会偏向短视频。不同视频时长下，用户观看行为的分布不同，原始目标不可比。

## 2. 方法

按视频时长分桶，在每个桶内统计观看时长或播放比例分布，将样本标签转化为桶内分位数：

```text
label = percentile(watch_time | duration_bucket)
```

或者：

```text
label = percentile(play_ratio | duration_bucket)
```

## 3. 应用

在精排模型中新增分位数目标 head：

```text
p_watch_quantile
```

训练时用分位数标签回归或分类。

最终排序时将其与长播、互动、负反馈目标融合：

```text
score =
  w1 * p_effective_view
+ w2 * watch_quantile_score
+ w3 * p_like
+ w4 * p_follow
- w5 * p_skip
```

## 4. 召回侧应用

U2I 双塔正样本不再简单定义为：

```text
watch_time > 10s
```

而是：

```text
watch_quantile > 0.7
```

或者作为样本权重：

```text
sample_weight = 1 + alpha * watch_quantile
```

## 5. 效果预期

```text
缓解长视频播放时长优势
缓解短视频完播率优势
提升不同长度视频排序公平性
提升用户真实满意度目标学习
```

---

# 七、最终总结

短视频推荐算法迭代，要突出以下业务特点：

```text
1. 隐式反馈为主：观看时长、完播、快划比点击更重要
2. 视频时长强干扰：需要分位数目标、时长消偏
3. 兴趣变化快：需要 session 建模、短期兴趣召回
4. 内容生命周期短：需要新鲜度和冷启动
5. 内容多模态强：文本、视觉、音频、作者都重要
6. 负反馈强：快划、不感兴趣、举报要显式建模
7. 连续消费体验重要：多样性、疲劳控制、长期价值不能忽视
```

如果落到具体算法，可以这样归纳：

```text
召回侧：
- U2I 多兴趣双塔
- session-aware U2I
- 分位数长播目标训练
- hard negative mining
- 多行为 ItemCF
- Swing/Graph CF
- 多模态向量 I2I
- KV 兴趣倒排召回
- 新视频冷启动召回

精排侧：
- 多目标 MMoE/PLE
- watch time / completion duration debias
- 分位数目标消偏
- 快划负反馈 head
- DIN/Transformer 序列建模
- 长短期兴趣融合
- 新鲜度/作者/内容质量建模
- score calibration
- 多样性和疲劳控制
- 长期价值建模
```

一句话总结：

> **短视频推荐的技术迭代核心，不是简单提升点击率，而是围绕“用户是否真正愿意持续看下去”来建模。召回要解决兴趣覆盖、实时兴趣和冷启动；精排要解决观看满意度、多目标融合、时长偏置、负反馈和连续消费体验。**
